## 2. 实际模型及准确训练目标

### 2.1 表示与打分

基础模型包含用户与物品嵌入表，Xavier uniform 初始化，维度 64。普通版本直接用嵌入；LightGCN 版本在训练交互图上采用对称度归一化邻接矩阵，传播 K 层，平均第 0 至 K 层表示。预测分数由未归一化表示的内积给出；官方测试代码再取 sigmoid，数学上不改变严格排序，但浮点饱和会引入额外并列。

来源：论文 §5.1.4，第 7 页；官方 `LightCCF.py` 的 `__init__`、`aggregate`、`forward` 和 `get_rating_for_test`。

### 2.2 邻域聚合（NA）损失：以代码为准的精确定义

一个批次有 B 个训练交互 `(u_b,i_b)`。记未归一化表示为 `e_u,e_i`，L2 归一化后为 `x_b=e_ub/||e_ub||`、`y_b=e_ib/||e_ib||`。代码实际执行：

\[
s_b=x_b^\top y_b/\tau,\quad
z_{bc}=(x_b^\top y_c+x_b^\top x_c)/\tau,\quad
q_b=\frac{\exp(s_b)}{\sum_{c=1}^{B}\exp(z_{bc})},\quad
\mathcal L_{NA}=-\frac1B\sum_b\log(q_b+10^{-5}).
\]

**实现必须注意：**

1. 两个相似度先相加，再指数化。`exp(UI + UU)` 与 `exp(UI) + exp(UU)` 不等价。
2. 不额外归一化 `x_c+y_c`；等价于对用户嵌入与“用户+物品”组合做内积，但该组合不是单位向量。
3. 只有用户作为锚点，没有额外物品到用户的对称损失。
4. 官方没有排除对角线、相同用户的重复行、其他已知正物品，整个 B×B 分母均保留。批内重复行不得去重。
5. `10e-6` 为 `1e-5`，并非 `1e-6`。该数加在概率比值上，不能随意替换成只给分母加 epsilon。
6. 如要稳定计算且严格保持该 epsilon，可令 `a_b=s_b-logsumexp(z_b)`，用 `-logaddexp(a_b, log(1e-5))`。直接用 `logsumexp(z)-s` 会省略官方平滑项，应标明差异或用数值/梯度等价测试验证其影响。

论文第 5 页式 (13) 将负对描述为排除当前用户的其他正对，式 (14) 改成批次正对，但没有给出 `e_p` 的明确代数定义。论文文字与代码的排除规则存在差异。本次课程复现宜明确采用官方实现定义，不悄悄添加 mask。

### 2.3 BPR 与正则项

官方代码：

\[
\mathcal L_{BPR}=-\frac1B\sum_b\log\left(\sigma(e_{u_b}^\top e_{i_b}-e_{u_b}^\top e_{j_b})+10^{-7}\right),
\]
\[
\mathcal L_{reg}=\frac{1}{2B}\sum_b
(\|e^{(0)}_{u_b}\|^2+\|e^{(0)}_{i_b}\|^2+\|e^{(0)}_{j_b}\|^2),\qquad
\mathcal L=\mathcal L_{BPR}+\alpha\mathcal L_{NA}+\beta\mathcal L_{reg}.
\]

BPR 使用未归一化、可能经过 GCN 的表示；正则使用批次所取的原始嵌入，并且重复出现的用户/物品会重复贡献。`10e-8=1e-7`。这里的 beta 不宜直接换成 Adam `weight_decay`：全参数权重衰减与批次嵌入正则不是同一目标。

论文第 5 页式 (15) 漏写 sigmoid，原文印为 `-log(sim_pos-sim_neg)`，图像核验确认不是 HTML 提取错误；直接照此实现会在差值非正时无定义。式 (16) 把正则简写为整个表示矩阵的平方范数，也不同于代码的批次均值形式。报告应准确写实际运行目标，并解释用作者代码消解公式歧义。

|---|---:|---:|---:|---:|

第 6–7 页 §5.1.2：按用户随机切分 80% 训练、20% 测试，评价 Recall@10/20、NDCG@10/20。没有说明独立验证集。

官方 `tester.py`：对每个测试用户，给所有物品打分，屏蔽训练交互物品，取 Top-K。Recall 每用户除以测试正物品数，NDCG 的 IDCG 是前 `min(K,测试正物品数)` 个位置的折扣和，最后按测试用户宏平均。该全物品、多正例协议与 ReChorus 逐交互、候选负采样、HR/NDCG 协议不能直接混同比较。

### 3.2 超参数

第 7 页 §5.1.4：嵌入 64；五次实验取平均；GCN 层数在 1、2、3 中考察；tau 搜索 `{0.20,0.22,0.24,0.26,0.28,0.30}`；alpha 搜索 `{0.1,0.5,1,2.5,5,10}`；beta=`0.0001`、学习率=`0.001`。RecDCL 的维度为 2048，是基线特例。

官方 `LightCCF.sh` 的推荐运行配置：

| 数据集 | 编码器 | 层数 | batch | tau | alpha |
|---|---|---:|---:|---:|---:|
| Douban-book | MF | 0 | 2048 | 0.28 | 1.0 |
| Tmall | MF | 0 | 4096 | 0.24 | 5.0 |
| Amazon-book | LightGCN | 3 | 4096 | 0.22 | 5.0 |

`parser.py` 默认训练最多 600 轮、early_stop=10、每轮评估一次、seed=2023。`trainer.py` 用 Adam；负采样遍历所有训练交互，每条交互采一个均匀随机物品，拒绝用户的训练正例，然后全局打乱三元组。因此每轮不会改采用户-正物品，只重新采负例。

### 3.3 官方训练代码的可复现问题

- `--seed` 存在，`tools.init_seed` 存在，但 `main.py` 和训练流程没有调用。因此只改变命令行 seed 不能可靠控制随机初始化/负采样/打乱。需在初始化模型之前设置 NumPy、Python、PyTorch/CUDA 种子并记录。
- 固定提交的 `main.py` 定义 `load_models()` 为零参数，却调用 `load_models(args)`，直接执行入口会抛出 `TypeError`。独立 Douban 锚点仅在内存中把此调用改成 `load_models()`；上游文件保留原样，并在结果 JSON 记录修正和源码 SHA256。
- 直接读取 `test_dict` 每轮评价，用测试 Recall@20 选择 epoch 和早停；没有独立验证集。`cnt > early_stop` 实际容许 11 次连续未提升才停止。课程实验应使用独立 dev 选模、保留 test 最终评价，同时声明与官方协议不同。
- 最终记录的是最好测试 Recall 对应的 NDCG，未保存最佳权重 checkpoint。复现实验应保存 dev 最优 checkpoint，并明确所有测试指标是否来自同一轮。
- 默认 `gpu=2` 对单卡机器不合适，应指定 GPU 0 或按实际环境处理。
- `num_batch=len//batch+1` 在恰好整除时多算一批；测试代码的断言会失败，训练记录的平均 loss 会偏低。可修复为上取整，不改变梯度。
- MF 仍在构造函数中创建/加载图邻接矩阵，尽管前向不使用。这是官方实现开销，不是 MF 模型数学必需。若移除，计时说明应区分初始化与训练耗时。
- 官方种子与五次均值的具体列表、方差、置信区间、t 检验实现均未给出，不能照抄“显著优于”的结论到自己的结果。

## 5. 理论解释应保持的边界（本次独立分析）

- 第 3–4 页式 (5)–(10) 的正项说明用户参数受到已交互物品方向的梯度吸引，这支持“优化过程中存在邻域信息传递”。但该式针对点积相似度、只考虑锚点偏导；官方使用归一化表示，并且表示同时作为其他行的候选，真实梯度需要归一化 Jacobian 与共享参数的其他项。
- 若 `x=e/||e||`，则 `∂x/∂e=(I-xxᵀ)/||e||`。因此不能直接把简化点积梯度解释为实际 Adam 参数更新，更不能声称和固定图卷积在所有条件下严格等价。
- 第 6 页式 (17)–(19) 的 `Y/E` 未给出矩阵除法定义；概率矩阵依赖当前表示，用户矩阵与物品概率的维度描述也不充分。它是邻域聚合的类比性解释，尚不足以作为一般严格等价定理。式 (18) 的迭代乘积写法也不清楚。报告可用“具有邻域信息聚合效应”而不复述成完整证明。
- 第 2 页把 `D^{-1/2} A D^{-1/2}` 称为 normalized Laplacian，但该表达式是对称归一化邻接矩阵；常用归一化拉普拉斯为 `I-D^{-1/2}AD^{-1/2}`。报告宜纠正术语。
- 无 GCN 不等于已经数学证明不存在过平滑；论文主要用性能变化支持相关解释。若未测量表示相似性/平滑度，不应把推荐效果改善当作过平滑被消除的直接证据。
- §5.3–5.4 把 Amazon normal 组较差表现归因为更多假正例，缺少独立假正例标注或因果实验，属于作者解释，不能写成已证实事实。

## 6. 方法局限与可设计的课程实验

- 每批 NA 时间复杂度 `O(B²d)`，显存含 `O(B²)` 得分矩阵；它比纯 BPR 的 `O(Bd)` 多一个 B 因子。论文表 3 的“仅略高”不应解释为对任意 batch 都低开销。显存限制而改 batch 会改变负对集合、目标尺度与训练动态，不是仅改变计算速度。
- 只有 ID 嵌入，无法仅凭模型处理完全未见用户/物品；无内容特征或时间序列信息，冷启动和偏好漂移仍是局限。
- 随机批次中的其他交互并不必然为语义负例。相同用户、相同物品、共同偏好以及流行物品会导致重复/假负例，且按交互抽样会提高活跃用户和热门物品的权重。
- 当前 NA 仍依赖 BPR，不能把组合模型改进全部归因于对比损失。至少比较同一协议下 BPR-MF、LightGCN、LightCCF，并通过 alpha=0 消融定位 NA 的增益。
- 如主结论未复现，先检查分母表达式、归一化、self/repeated mask、epsilon、BPR/正则尺度、padding ID、负采样屏蔽范围、dev/test 选择与候选集合；然后才排查合理超参数/数据差异。禁止为接近论文结果而反复按 test 调参。
- ReChorus 自带数据若和原论文不同，主要结论只能是“在课程指定数据和协议下是否观察到相同趋势”，不能声称数值级复现成功或失败。结果不如基线时仍可构成有效复现报告，前提是实现与评价审计通过，并如实讨论数据/协议/预算限制。

## 7. 建议交给主实验的核验关卡

1. 用小批次固定张量，与 `official_losses.py` 对照 BPR、reg、NA 值及嵌入梯度，覆盖重复用户、重复正物品、B=1、正常随机批次。
2. 检查采样物品 ID 在有效范围内，padding 不进入负样本/候选；模型只使用 train 构图；dev/test 正例未进入训练。
3. 用人工排序例子核对指标与候选集合；记录 ReChorus 固定候选文件的哈希和 split 计数。
4. 训练前固定种子，重复小运行核对相同初始损失和首轮指标；完整运行保留参数、日志、最优 checkpoint 与逐轮指标。
5. 每个配置只按 dev 指标选模；所有最终测试数值来自已选定 checkpoint。若运行种子数少于论文五次，清楚说明限制；无统计检验不使用“显著”。
